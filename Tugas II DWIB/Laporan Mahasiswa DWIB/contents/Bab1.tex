\section{Pengenalan DBT}\label{sec:pengenalan}
\istilah{Data Build Tool} (dbt)\index{dbt} adalah kerangka kerja sumber terbuka berbasis SQL dan templat Jinja untuk tahap \textbf{Transform} pada arsitektur data modern \istilah{ELT} (\istilah{Extract, Load, Transform}) \citep{handy2017,dbtdocs}. Pada ETL konvensional, data diolah di server perantara sebelum dimuat ke gudang data. Pada ELT, data mentah dimuat lebih dahulu ke dalam gudang data, lalu ditransformasi \emph{di dalam} gudang data tersebut memakai SQL \citep{reis2022}. dbt mengisi peran ``T'' itu: ia mengubah tabel mentah yang sudah berada di basis data menjadi tabel dimensi dan fakta yang siap dipakai aplikasi \istilah{Business Intelligence} (BI).

\subsection{Konsep dan Arsitektur DBT}
Arsitektur dbt bertumpu pada satu gagasan: \textbf{setiap transformasi adalah sebuah pernyataan \kode{SELECT}}. Pengembang cukup menulis \kode{SELECT}; dbt membungkusnya menjadi \kode{CREATE VIEW} atau \kode{CREATE TABLE AS} sesuai materialisasi, lalu mengeksekusinya melalui adapter basis data \citep{dbtdocs}. Konsep-konsep kunci dirangkum pada Tabel~\ref{tab:konsep}.

\begin{table}[H]
\centering\small
\caption{Konsep kunci dalam dbt.}\label{tab:konsep}
\begin{tabularx}{\linewidth}{>{\bfseries}l X}
\toprule
Konsep & Penjelasan \\
\midrule
Model\index{model} & Berkas \kode{.sql} berisi satu \kode{SELECT}. Satu berkas = satu model = satu \istilah{view}/tabel di basis data. \\

\end{table}

Saat perintah seperti \kode{dbt run} dijalankan, dbt bekerja dalam lima tahap:
\begin{enumerate}[nosep]
    \item \textbf{Parse}: membaca \kode{dbt\_project.yml}, \kode{profiles.yml}, seluruh model SQL, berkas YAML, dan macro.
    \item \textbf{Compile}: merender templat Jinja menjadi SQL murni (hasilnya dapat dilihat di \kode{target/compiled/}).
    \item \textbf{Bangun DAG}: menghitung ketergantungan antarmodel dari \kode{ref()} dan \kode{source()}.
    \item \textbf{Execute}: membungkus SQL sesuai materialisasi dan mengirimkannya ke basis data. Model yang tidak saling bergantung dijalankan paralel sesuai jumlah \istilah{threads}.
    \item \textbf{Artefak}: menyimpan \kode{manifest.json}, \kode{run\_results.json}, dan \kode{catalog.json} yang dipakai untuk dokumentasi dan \istilah{lineage}.
\end{enumerate}

Proyek kelompok menyusun model dalam lapisan (Subbab~\ref{sec:struktur}): \textbf{staging} (\istilah{raw} $\rightarrow$ bersih: \istilah{rename}, \istilah{cast}, \istilah{clean}), lalu \textbf{marts} berupa dimensi dan fakta (bersih $\rightarrow$ \istilah{star schema}: \istilah{join}, hitung, agregasi).

\subsection{Fitur dan Dukungan DBT}
Fitur utama dbt \citep{dbtdocs,shamimw}:
\begin{itemize}[nosep]
    \item \textbf{Pemodelan berbasis SQL}: transformasi dipecah menjadi model-model kecil yang saling merujuk lewat \kode{ref()}.
    \item \textbf{Manajemen dependensi otomatis}: urutan eksekusi diturunkan dari DAG, tidak ditulis manual.
    \item \textbf{Pengujian data}: test generik \kode{unique}, \kode{not\_null}, \kode{accepted\_values}, \kode{relationships}, ditambah \istilah{singular test} berupa SQL bebas.
    \item \textbf{Dokumentasi \& lineage otomatis}: \kode{dbt docs generate} menghasilkan situs kamus data dan grafik \istilah{lineage}.
    \item \textbf{Version control}: seluruh proyek berupa berkas teks yang dapat dikelola dengan Git dan diuji di CI/CD.
    \item \textbf{Incremental model}: hanya memproses data baru/berubah pada tabel besar.
    \item \textbf{Snapshot}: merekam perubahan data dari waktu ke waktu (SCD Type~2).
    \item \textbf{Ekosistem adapter}: satu proyek dapat dijalankan di basis data berbeda; proyek kelompok berjalan di DuckDB dan PostgreSQL \citep{dbtduckdb,dbtpostgres}.
\end{itemize}

\langkah{Keuntungan dan batasan.} Bagi tim data, keuntungan dbt dapat diringkas dalam empat hal \citep{handy2017,hirazone}: (1) \textbf{cukup SQL}: analis yang menguasai SQL dapat membangun \istilah{pipeline} tanpa menulis kode untuk DDL dan urutan eksekusi; (2) \textbf{andal dan dapat diulang}: karena setiap model hanya \kode{SELECT}, menjalankan ulang \kode{dbt run} menghasilkan tabel yang sama dari data yang sama (\istilah{idempoten}); (3) \textbf{teruji dan terdokumentasi}: test dan deskripsi ditulis berdampingan dengan kode; (4) \textbf{praktik rekayasa perangkat lunak}: \istilah{code review}, Git, dan CI. Batasannya: dbt tidak memindahkan data, dbt Core tidak menjadwalkan dirinya sendiri (perlu cron/Airflow), dan kemampuannya mengikuti basis data target. Pada studi kasus kelompok, dbt juga tidak lebih cepat daripada skrip manual untuk data kecil (Subbab~\ref{sec:tugas1}).

\subsection*{Dasar \istilah{Dimensional Modelling} (Kimball)}
\addcontentsline{toc}{subsection}{Dasar Dimensional Modelling (Kimball)}
\istilah{Dimensional modelling}\index{Kimball} menyusun data analitik menjadi dua jenis tabel \citep{kimball2013,kimballtech}: \textbf{tabel fakta}, yang mencatat ukuran numerik suatu peristiwa bisnis (berapa, berapa banyak), dan \textbf{tabel dimensi}, yang memberi konteks peristiwa tersebut (siapa, apa, di mana, kapan). Satu tabel fakta yang dikelilingi dimensi-dimensinya disebut \istilah{star schema}. Setiap \istilah{star schema} dirancang dengan empat langkah berurutan:
\begin{enumerate}[nosep]
    \item \textbf{Pilih proses bisnis}, misalnya pergerakan stok atau pembayaran pelanggan.
    \item \textbf{Tetapkan grain}\index{grain}, yaitu arti satu baris tabel fakta (mis. ``satu baris = satu pergerakan stok''), sebelum memilih kolom apa pun.
    \item \textbf{Identifikasi dimensi} yang konsisten dengan grain tersebut.
    \item \textbf{Identifikasi fakta}, yaitu ukuran numerik yang berlaku pada grain tersebut.
\end{enumerate}

\section{Data Quality dalam DBT}\label{sec:dataquality}
Kualitas data adalah syarat agar laporan BI dapat dipercaya. dbt menyediakan dua jenis pengujian yang dijalankan dengan \kode{dbt test} \citep{dbttests}:
\begin{enumerate}[nosep]
    \item \textbf{Generic test}, dideklarasikan di berkas YAML pada level kolom: \kode{unique}, \kode{not\_null}, \kode{accepted\_values}, dan \kode{relationships} (integritas \istilah{foreign key}). Test juga dapat dipasang pada tabel sumber (\istilah{source test}).
    \item \textbf{Singular test}, berupa berkas SQL di folder \kode{tests/} yang mengembalikan baris-baris pelanggar aturan. Test dinyatakan PASS bila kueri menghasilkan nol baris.
\end{enumerate}

Contoh \istilah{generic test} pada fakta proyek kelompok: setiap \istilah{foreign key} diberi \kode{not\_null} \emph{dan} \kode{relationships}, karena \kode{relationships} mengabaikan nilai \kode{NULL}.
\begin{lstlisting}[style=yml, caption={Potongan \kode{models/marts/schema.yml}.}, label={lst:genericyml}]
  - name: fact_inventory
    description: "Transaction fact. Grain: 1 baris = 1 pergerakan stok."
    columns:
      - name: transaction_id
        description: "Degenerate dimension."
        data_tests: [unique, not_null]
      - name: product_key
        data_tests:
          - not_null
          - relationships:
              arguments: {to: ref('dim_product'), field: product_key}
\end{lstlisting}
